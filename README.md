# Quran Complex — 21 إصداراً مصوّراً: ست روايات وثلاثة مصاحف واثنتا عشرة ترجمة

> **النسخة الحالية (الإصدار 2)** هي هذا التطبيق الكامل، وهي ما تظهر في الصفحة الرئيسية للمستودع. **النسخة الأولى** (ملف `index.html` القديم الخاص برواية حفص وحدها) لم تُحذف؛ بل أُرشفت في [`legacy/`](legacy/README.md) وفي الفرع `legacy-v1` لمن أراد الرجوع إليها أو تطويرها. الأرشيف غير مستعمل في البناء أو النشر، ولا يؤثر على روابط الصور لأنها على Blogger وpdfquran.com.

**قارئ مصاحف رقمي** يجمع **مصحف المدينة النبوية** بروايات **حفص، قالون، ورش، شعبة، السوسي والدوري**، وثلاثة إصدارات عربية من **pdfquran.com** (**المصحف العادي 1**، **المصحف العادي 2**، **المصحف الكبير**)، و**اثنتي عشرة ترجمة** إلى لغات العالم، في تطبيق واحد مبني بـ **React + Vite + TypeScript**. صفحات مصوّرة كاملة، فهرس السور والأجزاء، انتقال مباشر إلى أي صفحة، قراءة دون اتصال، وتوافق مع الجوال.

🔗 [الواجهة الرئيسية](https://qurancomplex.ly/) · [المعاينة المباشرة](https://gamingmonster2.github.io/hafs/) · [المستودع](https://github.com/Gamingmonster2/hafs)

📚 فهرس مُحسَّن لمحركات البحث: [الأجزاء الثلاثون](https://qurancomplex.ly/juz) · [كل المصاحف والترجمات](https://qurancomplex.ly/riwayat) · [جزء عم](https://qurancomplex.ly/juz-amma) · [جزء تبارك](https://qurancomplex.ly/juz-tabarak)

## ما الجديد في هذه النسخة

- **اثنتا عشرة ترجمة جديدة:** الأنكو، الصينية، الإنجليزية، الفرنسية، الهوساوية، الإندونيسية، البرتغالية، التاميل، التيلجو، التركية، الأوردو، والفيتنامية — كل ترجمة على نطاقها الفرعي الخاص.
- **صور مصغّرة للأغلفة:** بطاقات صفحة الهبوط تعرض غلاف كل مصحف وترجمة مثل موقع pdfquran.com، وشريط القارئ يعرض غلاف الإصدار الحالي. الصور محفوظة محلياً في `public/images/covers/` (21 غلافاً، نحو 145 KB) فلا تعتمد على موقع خارجي.
- **21 إصداراً في فهرس واحد:** صفحة `/riwayat` تعرض الروايات والمصاحف والترجمات مع صور أغلفتها وعدد صفحات كل منها.
- **بطاقات زجاجية بصور الصفحة الأولى:** الواجهة الرئيسية تعرض لكل إصدار صورة مصغّرة مضغوطة من صفحته الأولى (240×348، WebP جودة 72، نحو 18 KB) داخل «صندوق زجاجي» شفاف مع لمعان عند التحويم، والكتابة تحت الصورة. الصور مولّدة محلياً في `public/images/previews/` عبر `scripts/make-previews.py` (يستخدم Pillow، المعادل الوظيفي لأمر ImageMagick: تحجيم + ضغط WebP). للروايات الست تُنزَّل الصفحة الأولى من روابط Blogger الأصلية، وللترجمات والمصاحف من ملفات WebP المحلية.
- **روابط نطاقات مكتملة:** الـ Worker يوجّه كل النطاقات الفرعية الـ21 إلى نفس البناء، ويضيف عناوين وصفية وصور OG لكل إصدار.
- **جاهز للوكلاء الأذكياء:** ملفات `llms.txt` و`llms-full.txt` وفهارس JSON تسمح لأي مساعد دردشة أو محرك بحث بالحصول على الصفحة أو الصورة المطلوبة بطلب واحد، من غير زحف على 18,847 صفحة (انظر القسم أدناه).

## قراءة مريحة على أندرويد

- **جاهزة من أول لمسة:** عند فتح أي إصدار تظهر الصفحة كاملة داخل الشاشة (`object-fit: contain`) في الوضعين الرأسي والأفقي؛ لا يحتاج القارئ إلى تكبير أو تصغير متكرر قبل القراءة.
- **تكبير عند الطلب فقط:** أي ضغط على `+` أو `−` أو قرّب بإصبعين يخرج من وضع الملاءمة ويحفظ مستوى التكبير، وزر **⤢ ملاءمة** يعيد الصفحة فوراً لتعبئة الشاشة. المدى من **75% إلى 200%** بخطوات صغيرة قريبة من 100% (100 ← 110 ← 115 ← 125 ← 140 …) حتى لا تكبر الصفحة فجأة.
- **قلب صفحة أوضح:** سهمان أكبر حجماً عليهما «السابقة» و«التالية». الاتجاه عربي صحيح: زر «التالية» يشير إلى اليسار لأن الصفحة التالية تقع يسار الحالية في المصحف، والسحب من اليمين إلى اليسار يؤدي إلى الصفحة التالية.
- **صوت الورق:** عند قلب الصفحة يُسمع صوت تقليب حقيقي من الملف المرفق `public/audio/page-turn.mp3`، مضبوط على **ثانية واحدة** وبمستوى صوت **منخفض (22%)** مع تلاشٍ في الطرفين. يمكن كتمه فوراً من زر 🔊/🔇 في الشريط العلوي، أو من «المظهر والإعدادات» ← «صوت تقليب الصفحة». يعمل دون اتصال بعد الزيارة الأولى.
- **تركيز بلا أدوات:** الضغط مرة واحدة على الصفحة — أو زر 👁 — يخفي الشريطين والقوائم المنسدلة وكل الإعدادات، ويظهر زر عائم «إظهار الأدوات» للعودة. في ملء الشاشة تبقى الصفحة وزر الخروج الواضح فقط.
- **انسياب مع دوران الهاتف:** ارتفاع التطبيق يُحدَّث من `window.innerHeight` عند `resize` و`orientationchange`، فتبقى الصفحة ملائمة عند التبديل بين الرأسي والأفقي.
- **تثبيت كتطبيق:** زر «تثبيت الموقع كتطبيق» متاح في صفحة الهبوط وفي إعدادات القارئ. صفحة الهبوط تسجّل `landing-sw.js` وتستخدم نفس الـ manifest حتى يظهر طلب التثبيت فعلياً على `qurancomplex.ly`. يعتمد الزر على `beforeinstallprompt`، ومع غيابه تظهر رسالة ترشد إلى قائمة Chrome ← «تثبيت التطبيق» / «إضافة إلى الشاشة الرئيسية». لكل إصدار معرّف PWA مستقل؛ لأن النطاق الفرعي هو `scope` الخاص به.

> **حقوق صوت القلب:** الملف `public/audio/page-turn.mp3` من تأثير [Turn the page of a book](https://pixabay.com/sound-effects/film-special-effects-turn-the-page-of-a-book-442331/) للمستخدم [spinopel](https://pixabay.com/users/spinopel-46570060/) على Pixabay، ويُستخدم وفق [ترخيص Pixabay Content License](https://pixabay.com/service/license-summary/) الذي يسمح بالاستخدام المجاني في المشاريع.

## الترجمات الاثنتا عشرة

الترجمات مأخوذة من ملفات PDF المتاحة للتنزيل في [pdfquran.com](https://www.pdfquran.com/)، والمصدر المعلن للمصاحف هو **مجمع الملك فهد لطباعة المصحف الشريف**. رابط الملف الأصلي لكل ترجمة محفوظ في `sourcePdf` داخل `src/data/mushafs.ts` وفي ملف الفهرس `<id>-index.json`.

الصفحات حُوّلت إلى **WebP** بجودة 78 ومقياس 0.85 من صفحة PDF الأصلية (~459×689 بكسل)، وحُفظت داخل المستودع في `public/images/<id>/`، لذلك تعمل دون اتصال بعد الزيارة الأولى. اختيار المقياس بهذا الشكل يُبقي حجم الموقع المنشور دون حدّ GitHub البالغ 1 جيجابايت مع الحفاظ على وضوح النص (الصفحة تُعرض على الجوال بعرض يقارب 400 بكسل). لا توجد صفحات JPG جاهزة على pdfquran.com لهذه الترجمات (كل المحاولات أعادت 404)، فكان التحويل من PDF هو المسار الوحيد.

إعادة الاستيراد من ملفات PDF النزّلة:

```bash
# ضع ملفات anko.pdf ... vietnami.pdf في مجلد ثم:
npm run import:translations -- --pdf-dir "C:\path\to\pdfs" --workers 4
# أو ترجمة واحدة:
npm run import:translations -- --pdf-dir "..." --only english
```

رابط التنزيل لكل ترجمة يتبع النمط: `https://www.pdfquran.com/download/<id>/<id>-quran.pdf`.

**دقة الفهرس — بيان واضح:** فهرس كل ترجمة يحتوي 114 سورة و30 جزءاً.

- **أسماء السور وترتيبها وصفحات بدايتها:** مأخوذة من الإشارات المرجعية (bookmarks) الموجودة داخل ملف PDF نفسه، وقد تحقّقنا من تطابق أسماء السور الـ114 وترتيبها في الترجمات الـ12 كلها مع الترتيب الشرعي، وصحّحنا إشارة معكوسة في نهاية ملف الأنكو. هذه هي الأرقام المعتمدة.
- **صفحات بدايات الأجزاء:** **تقديرية وليست مؤكدة 100%**، لأن ملفات الترجمة لا تحمل ترقيم المصحف العربي. حُسبت بنسبة موضع بداية الجزء داخل سورته في مصحف المدينة، ثم طُبّقت على صفحات تلك السورة في الترجمة. لذلك تُعرض في القارئ وصفحات SEO بعلامة «≈» مع تنبيه صريح، ولا يُدعى أنها مطابقة لترقيم المصحف.
- أرقام صفحات الترجمة خاصة بها، ولا تطابق ترقيم المصحف العربي البالغ 604 صفحة.

## الصور المصغّرة للأغلفة

استجابةً لطلبك بتقليد طريقة عرض النسخ في موقع pdfquran.com، أضفنا غلافاً مصغّراً لكل إصدار من إصداراتنا الـ21:

- إصدارات pdfquran.com (الثلاثة المصاحف + 12 ترجمة): الغلاف الأصلي من `https://www.pdfquran.com/images/covers/<id>.webp`.
- روايات مصحف المدينة الستة: صورة أول صفحة قرآن من ملف الروابط نفسه (الصورة 4 لأن الصور 1–3 أغلفة)، مُصغَّرة محلياً.
- كلها محفوظة بصيغة WebP في `public/images/covers/` بالحجم 180×260، بإجمالي نحو 145 KB.
- تظهر في: بطاقات صفحة الهبوط على `qurancomplex.ly`، وشريط أدوات القارئ، وصفحات الفهرس الثابتة `/riwayat` و`/juz-*` و`/riwayah/*`.

## فحص روابط المصاحف والصور

```bash
npm run check:mushaf                    # كل الإصدارات الـ21
npm run check:mushaf -- --id=hafs       # إصدار واحد
npm run check:mushaf -- --limit=20      # أول 20 صفحة (اختبار سريع)
npm run check:mushaf -- --no-fail       # لا يُنهي الأوامر برمز خطأ عند وجود روابط مكسورة
```

يُنتج التقرير في `reports/<id>-health.json`. الروابط المحلية `/images/...` تُفحص من القرص مباشرة بلا طلب HTTP؛ والروابط البعيدة (Blogger) تُفحص بطلب `HEAD` مع بديل `GET`_range_. الروابط الأبطأ من 3500ms تُصنَّف كـ «بطيئة» (يمكن تغييرها بـ `--slow=5000`).

> ملاحظة: فحوص Blogger قد تُظهر فشلاً مؤقتاً عند التزامن العالي؛ أعد الفحص بتزامن أقل قبل اعتباره مكسوراً.

## النشر على Cloudflare Pages

- اربط المستودع بـ Cloudflare Pages.
- Build command: `npm run build`
- Build output: `dist`
- أضف المتغير `NODE_VERSION=20` أو أحدث.
- ملفا `public/_redirects` و `public/_headers` يُنسخان تلقائياً إلى `dist`، ويحتوي `_headers` على تخزين طويل لملفات `/images/*`.

## معمارية النشر (مستودع واحد + بوابة Worker)

- **المستودع `Gamingmonster2/hafs`** يحمل الكود وبيانات كل الإصدارات، ويُبنى مرة واحدة.
- **`worker/index.js`** هو واجهة النطاق: صفحة هبوط Glassmorphism على `qurancomplex.ly` ببطاقات أغلفة، وتوجيه ذكي للنطاقات الفرعية الـ21 إلى **نفس البناء الموحّد**. التصميم يستخدم design tokens بأسلوب shadcn/ui وتأثيرات Magic UI (Aurora / Spotlight / Shine border) بصيغة CSS مدمجة تعمل في Worker واحد.
- الكود يكتشف النطاق الفرعي تلقائياً ويفتح الإصدار المناسب (`mushafFromHost()` في `src/App.tsx`)، وتبقى القائمة المنسدلة ظاهرة للتنقّل بين الإصدارات، وتبقى `?mushaf=` و`?page=` تعملان أيضاً.
- `wrangler.toml` يضبط المسارات و`READER_BASE` (مصدر التطبيق). الافتراضي معاينة GitHub Pages، وبعد إنشاء مشروع Cloudflare Pages يُفضَّل ضبطه على `https://<CF_PAGES_PROJECT>.pages.dev/`.

### خطوات النشر على Cloudflare

1. أضف أسرار المستودع: `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` (صلاحيات `Workers Scripts:Edit` و`Account Settings:Read` و`Zone:DNS:Edit` للمنطقة `qurancomplex.ly`).
2. أضف متغير المستودع اختيارياً `READER_BASE = https://<project>.pages.dev/` إن أردت استخدام Pages بدل معاينة GitHub.
3. في DNS على Cloudflare: تأكد أن `qurancomplex.ly` و`*.qurancomplex.ly` **proxied** (سحابة برتقالية). مسارات الـ Worker في `wrangler.toml` تتولى الباقي، ولا حاجة لـ CNAME منفصل لكل إصدار.
4. الصق محتوى `https://raw.githubusercontent.com/Gamingmonster2/hafs/reader-preview/worker/index.js` في محرر الـ Worker على Cloudflare ثم انشر.
5. فحص سريع: `https://qurancomplex.ly/health` يجب أن يعرض `"router": "6.1-glass-previews"` مع كل النطاقات الـ21.

**لماذا لا مستودعات منفصلة؟** الواجهة والفهرس والمنطق مشتركة بالكامل؛ تكرارها 21 مرة يعني 21 نسخة تحتاج صيانة متزامنة.

## تحسين نتائج البحث (SEO)

- `npm run build:seo` (مُدمج في `npm run build`) يولّد:
  - `public/robots.txt` و`public/sitemap.xml`.
  - `sitemap-mushafs.xml`: روابط الرئيسية + الفهران + 30 جزءاً + 21 صفحة إصدار + صفحات بدايات السور والأجزاء لكل إصدار.
  - `sitemap-images.xml`: صور الصفحات موزّعة تحت صفحات الأجزاء الثلاثين التي تعرضها فعلاً، مع خريطتين مخصّصتين لـ[جزء عم](https://qurancomplex.ly/juz-amma) و[جزء تبارك](https://qurancomplex.ly/juz-tabarak).
  - **53 صفحة ثابتة**: 30 صفحة جزء، و21 صفحة إصدار (`/riwayah/<id>`)، وصفحتا فهرس (`/juz` و`/riwayat`). كل صفحة فيها عنوان ووصف عربيان فريدان، `canonical`، og tags، JSON-LD، وفهرس سور ومعاينة مصغّرة لكل صفحات الجزء محمّلة كسولة.
  - **`sitemap-pages.xml`**: خريطة مستقلة لأصل **18,847 صفحة مصوّرة**؛ لكل صفحة رابط خاص وصورة واحدة بعنوان ووصف، مثل `https://english.qurancomplex.ly/page/441`.
  - **صفحة مستقلة لكل صفحة في كل إصدار**: المسار `/page/<رقم>` على النطاق الفرعي (مثلاً `https://english.qurancomplex.ly/page/441`)، أو `/page/<id>/<رقم>` على النطاق الرئيسي (مثلاً `https://qurancomplex.ly/page/english/441`). كل صفحة تحمل عنواناً ووصفاً فريدين و`og:image` وبيانات `ImageObject` منظمة، مع روابط للصفحتين المجاورتين. أسماء السور مكتوبة بالعربية **والإنجليزية** (`Al-'Ankabut — The Spider`) في العنوان والوصف و`alt` الصورة، واسم الإصدار بالإنجليزية أيضاً، حتى تظهر الصفحة في بحث الصور العالمي عند البحث باسم سورة إنجليزي. صفحات الأجزاء الـ30 تشير مباشرة إلى صفحات الإصدارات الـ21، فتُكتشف بالروابط الداخلية لا بالخريطة وحدها.
- **أسماء الصور نصوص لا أرقام:** رابط الصورة المنشور في الخرائط و`og:image` وبيانات الوكلاء يظهر هكذا `https://qurancomplex.ly/images/english/al-ankabut-page-441.webp`، واسمه في `image:title` و`og:image:alt` هو `سورة العنكبوت (Al-'Ankabut — The Spider) — صفحة 441 ...`. الملف الأصلي على القرص يبقى `0441.webp`؛ الـ Worker يترجم الاسم النصي إلى الرقم داخلياً، فلا نحتاج إعادة تسمية 13,411 ملفاً ولا نكسر روابط القارئ الحالية.
- **بيانات مستقلة للروابط العميقة:** الرابط `https://english.qurancomplex.ly/?page=441` يحمل عنوان السورة ووصفها و`og:image` الخاص بالصفحة وJSON-LD داخل HTML الخام قبل تشغيل JavaScript، فيراه زائر السوشيال ومحرك البحث والوكيل مباشرةً. كذلك `src/seo.ts` يحدّث العنوان والوصف والكلمات المفتاحية و`canonical` و`og:image` وJSON-LD داخل القارئ بحسب **السورة والجزء والإصدار**، لا اسماً عاماً، وبالاسم الإنجليزي الكامل للسورة.
- الـ Worker يمرّر هذه الملفات على النطاق الرئيسي، ويضيف فهرساً مختصراً لكل الإصدارات وزر تثبيت التطبيق في صفحة الهبوط، ويُظهر `X-QC-Router: 6.1-glass-previews` في `/health`.
- بعد النشر: أرسل `https://qurancomplex.ly/sitemap.xml` في Google Search Console وBing Webmaster Tools (ويكفي إرسال الخريطة الرئيسية لأنها تشير إلى `sitemap-pages.xml` و`sitemap-images.xml`)، ثم اطلب فهرسة صفحات `/juz` و`/riwayat` وصفحتَي جزء عم وتبارك. ويمكنك أيضاً إرسال `https://qurancomplex.ly/sitemap-pages.xml` مباشرة لتسريع اكتشاف صفحات المصاحف الـ18,847.

## جاهزية الوكلاء الأذكياء (AI / LLM discovery)

الهدف أن يسأل المستخدم وكيله: «أين سورة العنكبوت في الترجمة الإنجليزية؟ فيعطيه الرابط والصورة مباشرةً بلا بحث عميق». لذلك وُلّدت طبقة بيانات آلية خفيفة:

- `npm run build:ai` (مُدمج في `npm run build`) يولّد:
  - **`llms.txt`** — دليل مختصر بصيغة [llms.txt](https://llmstxt.org/) يشرح للوكيل أين يجد البيانات وكيف يجيب على الأسئلة الشائعة.
  - **`llms-full.txt`** — الدليل نفسه + أسماء السور الـ114 بالعربية والإنجليزية + الإصدارات الـ21.
  - **`ai/editions.json`** — كل إصدار: نطاقه، عدد صفحاته، غلافه، معاينته، ومثال صفحة/صورة.
  - **`ai/surahs.json`** — السور الـ114 بالعربية والإنجليزية مع صفحات حفص (`Al-'Ankabut — The Spider`).
  - **`ai/pages.json`** — لكل إصدار: كل سورة مع صفحة البداية/Nهاية والجزء ورابط الصفحة ورابط الصورة المباشر (الملف الأهم، نحو 900 KB). روابط الصور هنا نصية باسم السورة مثل `al-ankabut-page-441.webp`، و`?format=json` يعطي صورة الصفحة المطلوبة حتى لو كانت داخل السورة لا في أولها.
  - **`ai/juz.json`** — الأجزاء الثلاثون بنطاقات صفحاتها.
- الـ Worker يمرّر هذه الملفات على `https://qurancomplex.ly/llms.txt` و`https://qurancomplex.ly/ai/...`.
- **تمثيل JSON لأي صفحة:** أضف `?format=json` إلى أي رابط صفحة، فيرجع الوكيل كائناً مضغوطاً فيه: الإصدار، رقم الصفحة، السورة (عربية/إنجليزية)، الجزء، رابط الصفحة، رابط الصورة المباشر، والصفحتان المجاورتان. مثالان:
  - `https://qurancomplex.ly/page/english/441?format=json`
  - `https://english.qurancomplex.ly/page/441?format=json`
- أرقام صفحات الأجزاء في الترجمات تقريبية ومعلَّمة بـ `≈` و`juzApproximate: true` في البيانات، كما هي في الواجهة.

## استيراد المصاحف والترجمات

```bash
# رواية جديدة من مستودع صور جاهز
npm run import:mushaf -- --repo=OWNER/REPO --id=warsh --name="مصحف ... — ورش" --riwayah="ورش عن نافع"

# إصدار عربي من صفحات JPG الجاهزة على pdfquran.com
npm run import:pdfquran

# ترجمة من ملف PDF
npm run import:translations -- --pdf-dir "..." --only urdu

# أغلفة كل الإصدارات
npm run import:covers
```

بعد أي استيراد: حدّث `quranPages` في `src/data/mushafs.ts` من طول ملف `*-pages.json`، ثم شغّل `npm run check:mushaf -- --id=<id>`.
