# Quran Complex — مصحف المدينة النبوية الرقمي بالروايات الستة وثلاثة إصدارات إضافية

[![Preview build](https://github.com/Gamingmonster2/hafs/actions/workflows/pages-preview.yml/badge.svg?branch=reader-preview)](https://github.com/Gamingmonster2/hafs/actions/workflows/pages-preview.yml)

**قارئ مصاحف رقمي** يجمع **مصحف المدينة النبوية** بروايات **حفص عن عاصم، قالون عن نافع، ورش عن نافع، شعبة عن عاصم، السوسي والدوري عن أبي عمرو**، إضافة إلى ثلاثة إصدارات طباعية (**المصحف العادي 1**، **المصحف العادي 2**، **المصحف الكبير**) في تطبيق واحد مبني بـ **React + Vite + TypeScript**. صفحات مصوّرة كاملة (604 صفحة لكل مصحف)، فهرس السور والأجزاء، انتقال مباشر إلى أي صفحة، قراءة دون اتصال، وتوافق مع الجوال.

🔗 [الواجهة الرئيسية](https://qurancomplex.ly/) · [المعاينة المباشرة](https://gamingmonster2.github.io/hafs/) · [المستودع](https://github.com/Gamingmonster2/hafs)

📚 فهرس مُحسَّن لمحركات البحث: [الأجزاء الثلاثون](https://qurancomplex.ly/juz) · [الروايات الستة](https://qurancomplex.ly/riwayat) · [جزء عم](https://qurancomplex.ly/juz-amma) · [جزء تبارك](https://qurancomplex.ly/juz-tabarak)

كل مصحف له روابطه وفهرسه في ملف منفصل يُحمّل عند اختياره فقط، لذلك لا تتضخم حزمة التحميل الأولى. التطبيق يضم **9 مصاحف** (6 روايات + 3 إصدارات إضافية) و**5,436 صفحة قرآن**، و**5,636 صورة** (3,824 عن بُعد + 1,812 WebP محلية). فُحصت صور الإصدارات الثلاثة الجديدة: **604/604 لكل مصحف، بدون رابط مكسور**.

## قراءة مريحة على أندرويد

- **جاهزة من أول لمسة:** عند فتح أي رواية تظهر الصفحة كاملة داخل الشاشة (`object-fit: contain`) في الوضعين الرأسي والأفقي؛ لا يحتاج القارئ إلى تكبير أو تصغير متكرر قبل القراءة.
- **تكبير عند الطلب فقط:** أي ضغط على `+` أو `−` أو قرّب بإصبعين يخرج من وضع الملاءمة ويحفظ مستوى التكبير، وزر **⤢ ملاءمة** يعيد الصفحة فوراً لتعبئة الشاشة. المدى من **75% إلى 200%** بخطوات صغيرة قريبة من 100% (100 ← 110 ← 115 ← 125 ← 140 …) حتى لا تكبر الصفحة فجأة.
- **قلب صفحة أوضح:** سهمان أكبر حجماً مع كلمتَي «السابقة» و«التالية». الاتجاه عربي صحيح: زر «التالية» يشير إلى اليسار لأن الصفحة التالية تقع يسار الحالية في المصحف، والسحب من اليمين إلى اليسار يؤدي إلى الصفحة التالية.
- **صوت الورق:** عند قلب الصفحة يُسمع صوت تقليب حقيقي من الملف المرفق `public/audio/page-turn.mp3`، مضبوط على **ثانية واحدة** وبمستوى صوت **منخفض (22%)** مع تلاشٍ في الطرفين. يمكن كتمه فوراً من زر 🔊/🔇 في الشريط العلوي، أو من «المظهر والإعدادات» ← «صوت تقليب الصفحة». يعمل دون اتصال بعد الزيارة الأولى.
- **تركيز بلا أدوات:** الضغط مرة واحدة على الصفحة — أو زر 👁 — يخفي الشريطين والقوائم المنسدلة وكل الإعدادات، ويظهر زر عائم «إظهار الأدوات» للعودة. في ملء الشاشة تبقى الصفحة وزر الخروج الواضح فقط.
- **انسياب مع دوران الهاتف:** ارتفاع التطبيق يُحدَّث من `window.innerHeight` عند `resize` و`orientationchange`، فتبقى الصفحة ملائمة عند التبديل بين الرأسي والأفقي.
- **تثبيت كتطبيق:** زر «تثبيت الموقع كتطبيق» متاح في صفحة الهبوط وفي إعدادات القارئ. صفحة الهبوط تسجّل `landing-sw.js` وتستخدم نفس الـ manifest حتى يظهر طلب التثبيت فعلياً على `qurancomplex.ly`. يعتمد الزر على `beforeinstallprompt`، ومع غيابه تظهر رسالة ترشد إلى قائمة Chrome ← «تثبيت التطبيق» / «إضافة إلى الشاشة الرئيسية». لكل رواية معرّف PWA مستقل؛ لأن النطاق الفرعي هو `scope` الخاص به.

> **حقوق صوت القلب:** الملف `public/audio/page-turn.mp3` من تأثير [Turn the page of a book](https://pixabay.com/sound-effects/film-special-effects-turn-the-page-of-a-book-442331/) للمستخدم [spinopel](https://pixabay.com/users/spinopel-46570060/) على Pixabay، ويُستخدم وفق [ترخيص Pixabay Content License](https://pixabay.com/service/license-summary/) الذي يسمح بالاستخدام المجاني في المشاريع.

## إصدارات مصحف المدينة الإضافية (pdfquran.com)

أُضيفت ثلاثة إصدارات طباعية من **مصحف المدينة برواية حفص** إلى نفس القارئ، بترقيم صفحات مطابق للروايات الستة (604 صفحة، والصفحة 1 = الفاتحة):

| المعرّف | الاسم | النطاق | عدد الصفحات |
| --- | --- | --- | --- |
| `standard1` | المصحف العادي 1 | `standard1.qurancomplex.ly` | 604 |
| `standard2` | المصحف العادي 2 | `standard2.qurancomplex.ly` | 604 |
| `big` | المصحف الكبير | `big.qurancomplex.ly` | 604 |

الصور مأخوذة من صفحات المصحف الجاهزة في [pdfquran.com](https://www.pdfquran.com/) (المصدر المعلن: مجمع الملك فهد لطباعة المصحف الشريف)، ومحفوظة داخل المستودع بصيغة **WebP** في `public/images/<id>/`، لذلك تعمل دون اتصال ولا تعتمد على بقاء الموقع الخارجي. الفهرس مستخدم من ترقيم مصحف المدينة نفسه، وقد تحقّقنا من تطابق بدايات السور مع فهرس حفص.

لإعادة استيراد الصور أو تحديثها:

```bash
npm run import:pdfquran
```

النطاقات الفرعية الثلاثة تحتاج سجلات DNS تشير إلى نفس الـ Worker، ثم تُحدَّث الإصدارية في `/health` إلى `4.0-pdfquran-editions`.

## فحص روابط المصاحف

```bash
npm run check:mushaf                    # كل المصاحف
npm run check:mushaf -- --id=hafs       # مصحف واحد
npm run check:mushaf -- --limit=20      # أول 20 صفحة (اختبار سريع)
npm run check:mushaf -- --no-fail       # لا يُنهي الأوامر برمز خطأ عند وجود روابط مكسورة
```

يُنتج التقرير في `reports/<id>-health.json` ويتضمن: الرابط، الحالة، زمن الاستجابة، نوع المحتوى، والحجم.
الروابط الأبطأ من 3500ms تُصنَّف كـ «بطيئة» (يمكن تغييرها بـ `--slow=5000`).

**نتيجة الفحص الشامل للستة مصاحف (3,824 رابطاً):** 0 روابط مكسورة. متوسط الاستجابة من 1.16s إلى 1.57s حسب الرواية — وهذا يفسّر بطء النسخة القديمة التي كانت تحمّلها كلها دفعة واحدة.

> ملاحظة: قد يُظهر `npm audit` تحذيراً من حزمة `picomatch` التابعة لـ Vite (ReDoS في مطابقة الأنماط). لا يوجد إصلاح منشور بعد في الحزمة نفسها، وهو يؤثر على أدوات التطوير فقط وليس على ملفات الموقع المنشورة.

## إضافة مصحف جديد

1. أنشئ `src/data/<id>-pages.json` يحتوي على مصفوفة روابط الصور بالترتيب (مثل `hafs-pages.json`).
2. أضف كائن المصحف إلى مصفوفة `mushafs` في `src/data/mushafs.ts`:

```ts
{
  id: 'warsh',
  name: 'مصحف ... — رواية ورش عن نافع',
  shortName: 'ورش',
  riwayah: 'ورش عن نافع',
  loadPages: () => import('./warsh-pages.json'),
  loadIndex: () => import('./warsh-index.json'),
  coverPages: 3,
  quranPages: 604,
  accent: '#8a5a2b',
}
```

3. الواجهة، الفهرس، حفظ الجلسة، وفحص الروابط تعمل تلقائياً للمصحف الجديد.

### ترقيم الصفحات والفهرس (جميع المصاحف الستة)

النمط نفسه في الستة مصاحف (عدا السوسي الذي فيه 624 صورة): الصور 1-3 أغلفة، والصورة 4 هي الفاتحة = صفحة المصحف 1:

| الصور في الملف | المعنى | ما يظهر في الواجهة |
| --- | --- | --- |
| 1 – 3 | أغلفة فقط | «غلاف 1» … «غلاف 3» |
| 4 – 607 | صفحات القرآن (الفاتحة في الصورة 4) | `1` … `604` |
| 608 – 640 | صفحات الفهرس في نهاية المصحف | «فهرس 1» … «فهرس 33» |

لذلك أضفنا في `src/data/mushafs.ts` الحقلين `coverPages: 3` و `quranPages: 604`، وصار الرابط `?page=120` يعني **صفحة المصحف 120** (الصورة 123).

الفهرس الآن **فهرس سور وأجزاء** وليس شبكة أرقام:
- لكل مصحف ملف `<id>-index.json` فيه 114 سورة و30 جزءاً مع رقم الصفحة لكل منها.
- المصدر: [Quran.com API v4](https://api.quran.com/api/v4/chapters) — ترقيم مصحف المدينة النبوية المعتمد (604 صفحة).
- للتوليد مجدداً: `npm run build:index -- --id=hafs`.
- **يتطلب مطابقة بصرية يدوية** مع الصور قبل الاعتماد النهائي؛ هذا ما سيتولاه المستخدم.
- بحث الأرقام أُبقي كحقل صغير في أعلى الفهرس فقط لمن يريد الوصول السريع، وحُذفت شبكة الأرقام الكبيرة.

## النشر على Cloudflare Pages

- اربط المستودع بـ Cloudflare Pages.
- Build command: `npm run build`
- Build output: `dist`
- أضف المتغير `NODE_VERSION=20` أو أحدث.
- ملفا `public/_redirects` و `public/_headers` يُنسخان تلقائياً إلى `dist`.
- المشروع يُنشر عبر `.github/workflows/deploy.yml` عند الدفع إلى `main` أو فروع `preview/**`.
- النطاقات الفرعية تُدار بواسطة الـ Worker (انظر القسم التالي)، لذا لا تُربط يدوياً بمشروع Pages.

## معمارية النشر (مستودع واحد + بوابة Worker)

- **المستودع `Gamingmonster2/hafs`** يحمل الكود وبيانات المصاحف الستة، ويُبنى مرة واحدة.
- **`worker/index.js`** هو واجهة النطاق: صفحة هبوط Glassmorphism على `qurancomplex.ly`، وتوجيه ذكي للنطاقات الفرعية الستة إلى **نفس البناء الموحّد** (وليس إلى المستودعات القديمة المنفصلة). التصميم يستخدم design tokens بأسلوب shadcn/ui وتأثيرات Magic UI (Aurora / Spotlight / Shine border) بصيغة CSS مدمجة تعمل في Worker واحد.
- الكود يكتشف النطاق الفرعي تلقائياً ويفتح الرواية المناسبة (`mushafFromHost()` في `src/App.tsx`)، وتبقى القائمة المنسدلة ظاهرة للتنقّل بين الروايات، وتبقى `?mushaf=` و`?page=` تعملان أيضاً.
- `wrangler.toml` يضبط المسارات و`READER_BASE` (مصدر التطبيق). الافتراضي معاينة GitHub Pages، وبعد إنشاء مشروع Cloudflare Pages يُفضَّل ضبطه على `https://<CF_PAGES_PROJECT>.pages.dev/`.

### خطوات النشر على Cloudflare

1. أضف أسرار المستودع: `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` (صلاحيات `Workers Scripts:Edit` و`Account Settings:Read` و`Zone:DNS:Edit` للمنطقة `qurancomplex.ly`).
2. أضف متغير المستودع اختيارياً `READER_BASE = https://<project>.pages.dev/` إن أردت استخدام Pages بدل معاينة GitHub.
3. في DNS على Cloudflare: تأكد أن `qurancomplex.ly` و`*.qurancomplex.ly` **proxied** (سحابة برتقالية). مسارات الـ Worker في `wrangler.toml` تتولى الباقي، ولا حاجة لـ CNAME منفصل لكل رواية.
4. ادفع إلى `reader-preview` (أو شغّل `workflow_dispatch`): `deploy.yml` ينشر `dist/` على Pages، و`deploy-worker.yml` ينشر البوابة.
5. فحص سريع: `https://qurancomplex.ly/health` يعرض المسارات والمصدر الحالي.

**لماذا لا مستودعات منفصلة؟** الواجهة والفهرس والمنطق مشتركة بالكامل؛ تكرارها 6 مرات يعني 6 نسخ تحتاج صيانة متزامنة. كما أن توجيه Worker إلى المستودعات القديمة يُفقدنا التحسينات الجديدة (تحميل صفحة واحدة، الفهرس، الفلاتر، وضع التركيز، PWA).

## تحسين نتائج البحث (SEO)

- `npm run build:seo` (مُدمج في `npm run build`) يولّد من بيانات الفهارس وروابط الصور:
  - `public/robots.txt` و`public/sitemap.xml`.
  - `sitemap-mushafs.xml`: **909 روابط** (الرئيسية + الفهران + 30 جزءاً + 6 روايات + صفحات الروايات + 30 جزءاً و114 سورة لكل رواية).
  - `sitemap-images.xml`: **3,624 صورة** (604 صفحة × 6 روايات)، موزّعة تحت صفحات الأجزاء الثلاثين التي تعرضها فعلاً. مع خريطتين مخصّصتين لـ[جزء عم](https://qurancomplex.ly/juz-amma) و[جزء تبارك](https://qurancomplex.ly/juz-tabarak).
  - **38 صفحة ثابتة**: 30 صفحة جزء (`/juz-1` … `/juz-30`، و`/juz-amma` و`/juz-tabarak`)، 6 صفحات رواية (`/riwayah/<id>`)، وصفحتا فهرس (`/juz` و`/riwayat`). كل صفحة فيها عنوان ووصف عربيان فريدان، `canonical`، og tags، JSON-LD (WebSite + CollectionPage + ItemList + BreadcrumbList)، وفهرس سور ومعاينة مصغّرة لكل صفحات الجزء محمّلة كسولة ومرتبطة بالقارئ.
- الـ Worker يمرّر هذه الملفات على النطاق الرئيسي، ويضيف فهرساً مختصراً لكل الأجزاء والروايات وزر تثبيت التطبيق في صفحة الهبوط، ويُظهر `X-QC-Router: 3.1-reading-install` في `/health`.
- `src/seo.ts` يحدّث لكل صفحة قرآن داخل القارئ: العنوان، الوصف، الكلمات المفتاحية، `canonical`، `og:image`، وJSON-LD — بحسب **السورة والجزء والرواية**، لا اسماً عاماً.

## النسخة التجريبية المنشورة الآن

النسخة الحالية منشورة على فرع `gh-pages` في المستودع `Gamingmonster2/hafs`:

- **رابط المعاينة:** https://gamingmonster2.github.io/hafs/
- **رابط النطاق المرتبط:** http://ly.id.ly/hafs/
- **الكود المصدر:** فرع `reader-preview` في نفس المستودع.
- الفرع `main` ما زال يحتوي نسخة `index.html` القديمة untouched.

كل دفع على `reader-preview` يشغّل `.github/workflows/pages-preview.yml` فيبني المشروع وينشر `dist/` تلقائياً إلى `gh-pages`.

وللنشر على Cloudflare (للنطاق الأصلي لاحقاً) أضفت `.github/workflows/deploy.yml` أيضاً:

1. في إعدادات المستودع → Secrets and variables → Actions، أضف:
   - `CLOUDFLARE_API_TOKEN` (Secret) بصلاحية `Pages:Edit`.
   - `CLOUDFLARE_ACCOUNT_ID` (Secret).
   - `CF_PAGES_PROJECT` (Variable) مثل `qurancomplex-preview`.
2. ادفع أي فرع `preview/**` أو `dev` → يُنشأ Deploy Preview برابط خاص به.
3. الدفع على `main` → يُحدَّث مشروع Cloudflare المحدد.
4. عند اكتمال كل المصاحف وتأكيد الفحص، غيّر `CF_PAGES_PROJECT` أو أضف workflow إنتاجي للنطاق الأصلي.

> نشر معاينة GitHub Pages تم فعلياً من هنا باستخدام بيانات الدخول المخزّنة. أما Cloudflare فيحتاج إضافة الأسرار المذكورة أعلاه قبل تفعيله.

## استيراد المصاحف المتبقية

```bash
npm run import:mushaf -- --repo=OWNER/REPO --id=warsh --name="مصحف ... — ورش" --riwayah="ورش عن نافع"
```

يستنسخ المستودع، يستخرج كل روابط الصور، يرتبها حسب رقم الملف، ويكتب `src/data/<id>-pages.json` ثم يطبع لك الكائن الذي تضيفه إلى `src/data/mushafs.ts`. بعدها:

```bash
npm run check:mushaf -- --id=warsh
```

## خريطة التطوير القادمة

1. فحص بقية المصاحف واستخراج روابطها إلى ملفات `*-pages.json`، ثم إضافتها للسجل.
2. بناء خريطة (صفحة ← سورة / جزء / ربع) لكل مصحف بعد التحقق البصري، ثم إضافة فهرس الأجزاء.
3. نقل الصور من Blogger إلى تخزين مستقر (R2) تدريجياً مع الإبقاء على الروابط الحالية كنسخة احتياطية.
4. مطابقة `hafs-index.json` بصرياً مع الصور (608–640) وتصحيح أي فروق، ثم تعميم الفهرس على بقية المصاحف.
5. إضافة مقارنة صفحة بصفحة بين الروايات والبحث داخل الفهارس.
