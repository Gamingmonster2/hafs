# Quran Complex — قارئ المصاحف الرقمية (إعادة البناء)

مشروع جديد موحّد يجمع المصاحف في مستودع واحد، مبني بـ **React + Vite + TypeScript**.
النسخة الحالية تبدأ بمصحف **حفص عن عاصم** (640 صفحة مصوّرة)، مع تصميم يسمح بإضافة بقية الروايات لاحقاً دون تعديل الواجهة.

## لماذا إعادة البناء؟

| المشكلة في النسخة القديمة | الحل هنا |
| --- | --- |
| تحميل 640 صورة دفعة واحدة عند فتح الموقع | تحميل **صفحة واحدة فقط** + تحميل مسبق للصفحتين المجاورتين |
| لا يوجد انتقال مباشر لصفحة محددة | حقل رقم الصفحة + فهرس كامل + قفزات سريعة + رابط `?page=120` |
| الجلسة غير موثوقة | حفظ الصفحة والتكبير لكل مصحف في `localStorage` + استعادة تلقائية |
| لا يوجد فحص للروابط | سCRIPT فحص مستقل ينتج تقريراً لكل مصحف |
| مصدر واحد لكل مصحف ونطاق منفصل | سجل مصاحف مركزي `src/data/mushafs.ts` |
| الاعتماد على سكربت قديم ضخم في ملف HTML واحد | مكوّنات React منفصلة وقابلة للتطوير |

## فحص روابط المصاحف

```bash
npm run check:mushaf                    # كل المصاحف
npm run check:mushaf -- --id=hafs       # مصحف واحد
npm run check:mushaf -- --limit=20      # أول 20 صفحة (اختبار سريع)
npm run check:mushaf -- --no-fail       # لا يُنهي الأوامر برمز خطأ عند وجود روابط مكسورة
```

يُنتج التقرير في `reports/<id>-health.json` ويتضمن: الرابط، الحالة، زمن الاستجابة، نوع المحتوى، والحجم.
الروابط الأبطأ من 3500ms تُصنَّف كـ «بطيئة» (يمكن تغييرها بـ `--slow=5000`).

**نتيجة الفحص الأولي لمصحف حفص (640 رابطاً):** 640 سليمة، 0 مكسورة، 8 بطيئة، متوسط الاستجابة ~1627ms لكل صورة — وهذا يفسّر بطء النسخة القديمة التي كانت تحمّلها كلها دفعة واحدة.

> ملاحظة: قد يُظهر `npm audit` تحذيراً من حزمة `picomatch` التابعة لـ Vite (ReDoS في مطابقة الأنماط). لا يوجد إصلاح منشور بعد في الحزمة نفسها، وهو يؤثر على أدوات التطوير فقط وليس على ملفات الموقع المنشورة.

## إضافة مصحف جديد

1. أنشئ `src/data/<id>-pages.json` يحتوي على مصفوفة روابط الصور بالترتيب (مثل `hafs-pages.json`).
2. أضف كائن المصحف إلى مصفوفة `mushafs` في `src/data/mushafs.ts`:

```ts
{
  id: 'warsh',
  name: 'مصحف ... — رواية ورش عن نافع',
  shortName: 'ورش',
  riwayah: 'ورش عن نافع',
  pages: warshPages,
  sourcePdf: '...',
  accent: '#8a5a2b',
}
```

3. الواجهة، الفهرس، حفظ الجلسة، وفحص الروابط تعمل تلقائياً للمصحف الجديد.

> ملاحظة مهمة: الترقيم الحالي في `hafs-pages.json` هو ترقيم ملفات المصدر (`mumtaz-1-001.jpg` … `mumtaz-1-640.jpg`) وليس بالضرورة ترقيم صفحات مصحف المدينة المعروف (604 صفحة). لم نضف فهرس أجزاء/سور لأننا لا نملك خريطة موثوقة بعد؛ أضف ملف خريطة لاحقاً واربطه برقم الصفحة.

## البنية

```
src/
├─ App.tsx                  State الرئيسي: المصحف، الصفحة، التكبير، الجلسة
├─ components/
│  ├─ Toolbar.tsx           اختيار المصحف، المظهر، ملء الشاشة، الفهرس
│  ├─ PageViewer.tsx        عرض صفحة واحدة + السحب للتنقل + حالات التحميل/الخطأ
│  ├─ BottomBar.tsx         تنقل، قفز، علامة، تكبير، حفظ أوفلاين
│  └─ PageIndexDrawer.tsx   فهرس الصفحات والبحث السريع
├─ data/
│  ├─ mushafs.ts            سجل المصاحف
│  └─ hafs-pages.json       640 رابط صورة (من مستودع Gamingmonster2/hafs)
└─ hooks/usePersistentState.ts
public/sw.js                تخزين الصفحات التي زارها المستخدم + حفظ الصفحة عند الطلب
scripts/check-mushaf.mjs    فحص صحة الروابط
```

## النشر على Cloudflare Pages

- اربط المستودع بـ Cloudflare Pages.
- Build command: `npm run build`
- Build output: `dist`
- أضف المتغير `NODE_VERSION=20` أو أحدث.
- ملفا `public/_redirects` و `public/_headers` يُنسخان تلقائياً إلى `dist`.
- اربط النطاقات الفرعية (`hafs.qurancomplex.ly` …) بنفس المشروع؛ المصحف يُفتح مباشرة عبر `?mushaf=hafs&page=…`، ويمكن لاحقاً تحويل المسارات إلى مجلدات ثابتة.

## النسخة التجريبية على مستودع GitHub (تلقائياً)

أضفت `.github/workflows/deploy.yml`. بعد رفع المشروع إلى مستودع GitHub:

1. في إعدادات المستودع → Secrets and variables → Actions، أضف:
   - `CLOUDFLARE_API_TOKEN` (Secret) بصلاحية `Pages:Edit`.
   - `CLOUDFLARE_ACCOUNT_ID` (Secret).
   - `CF_PAGES_PROJECT` (Variable) مثل `qurancomplex-preview`.
2. ادفع أي فرع `preview/**` أو `dev` → يُنشأ Deploy Preview برابط خاص به.
3. الدفع على `main` → يُحدَّث مشروع Cloudflare المحدد.
4. عند اكتمال كل المصاحف وتأكيد الفحص، غيّر `CF_PAGES_PROJECT` أو أضف workflow إنتاجي للنطاق الأصلي.

> لم أستطع إنشاء المستودع أو النشر من هنا: لا يوجد `gh` ولا `wrangler` ولا رموز دخول في هذه البيئة. لكن ملف الـ workflow جاهز ويعمل فور توفيرها.

## استيراد المصاحف المتبقية

```bash
npm run import:mushaf -- --repo=OWNER/REPO --id=warsh --name="مصحف ... — ورش" --riwayah="ورش عن نافع"
```

يستنسخ المستودع، يستخرج كل روابط الصور، يرتبها حسب رقم الملف، ويكتب `src/data/<id>-pages.json` ثم يطبع لك الكائن الذي تضيفه إلى `src/data/mushafs.ts`. بعدها:

```bash
npm run check:mushaf -- --id=warsh
```

## خريطة التطوير القادمة

1. فحص بقية المصاحف واستخراج روابطها إلى ملفات `*-pages.json`، ثم إضافتها للسجل.
2. بناء خريطة (صفحة ← سورة / جزء / ربع) لكل مصحف بعد التحقق البصري، ثم إضافة فهرس الأجزاء.
3. نقل الصور من Blogger إلى تخزين مستقر (R2) تدريجياً مع الإبقاء على الروابط الحالية كنسخة احتياطية.
4. تمييز صفحات البداية/النهاية في مصحف حفص إذا تبيّن أن الـ 640 تشمل مقدمة وفهارس.
5. إضافة مقارنة صفحة بصفحة بين الروايات والبحث داخل الفهارس.
